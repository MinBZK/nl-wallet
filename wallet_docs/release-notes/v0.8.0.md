# v0.8.0 (dev)

## Upgrading

- The `pid_attributes` section of the wallet configuration has a new format. The
  path to an mdoc attribute is now an object with `namespace` and `element_name`
  instead of an array. The SD-JWT attribute paths are still arrays of claim
  names, but are now called `login_path` and `recovery_code_path`. The claim
  names `_sd` and `...` are rejected, as SD-JWT reserves them. For example:

    ```json
    "pid_attributes": {
      "mso_mdoc": {
        "eu.europa.ec.eudi.pid.1": {
          "login": { "namespace": "eu.europa.ec.eudi.pid.nl.1", "element_name": "bsn" },
          "recovery_code": { "namespace": "eu.europa.ec.eudi.pid.nl.1", "element_name": "recovery_code" }
        }
      },
      "sd_jwt": {
        "urn:eudi:pid:nl:1": { "login_path": ["bsn"], "recovery_code_path": ["recovery_code"] }
      }
    }
    ```

## Interoperability improvements

- PID issuance and PIN recovery now also work with a PID issuer that does not
  offer credential previews.
- When renewing the PID or recovering the PIN, the wallet now only detects that
  the user logged in with the DigiD account of someone else after the PIN has
  been entered, and then discards the received PID. This is also the case when
  the PID issuer offers credential previews.

## Bug fixes

- Cards received without credential previews now renew a matching card in the
  wallet, instead of always being added as a new card.
- The wallet app no longer freezes on iOS 27.2 and later when it checks the
  notification permission shortly after the device has (re)started, on the
  dashboard or in the notification settings.
- On iOS 27, scheduling local notifications without notification permission no
  longer fails with an error.

## Wallet app improvements

- Update to Flutter 3.50.0.
- The iOS app is now built with Xcode 27.2 (iOS 27 SDK).
